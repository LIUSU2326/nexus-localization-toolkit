# TransMate UI 重构预览

这是一个与现有业务页面隔离的 HTML/CSS/JS 预览，不会替换原来的 `index.html`，也不会触碰 `script.js` 的固定 DOM 依赖。

## 打开方式

直接打开 `index.html` 即可查看。若浏览器限制本地文件脚本，也可以在 `nexus-localization-toolkit` 目录运行：

```powershell
python -m http.server 4173
```

然后访问 `http://127.0.0.1:4173/ui-preview/`。

## 这版预览验证的方向

- 左侧导航按“工作流 / 工具 / 资源”分组，AI 配置移到独立抽屉。
- 文本翻译和本地化检测统一使用三步工作流：数据范围 → 策略 → 检查与导出。
- 复杂选项默认折叠，底部只保留一个主操作，结果预览与配置并排但不互相抢占层级。
- 本地化检测把问题收敛为一条可筛选的队列，优先处理真实失败、占位符和疑似未翻译。
- 保留 Ctrl/Cmd + K、通道切换、筛选、折叠、运行模拟等交互，便于评估信息架构。

## 现有项目的设计审计结论

目前没有独立的设计规范文件。`README.md` 仍描述 Retro-Futurism（紫色渐变、CRT 扫描线、霓虹发光），而 `styles.css` 后段又追加了多轮浅色 workbench / image replication / Cursor refinement 覆盖层。当前 CSS 存在多组重复 token 和多次 `:root`、`body` 重定义，说明是连续叠加而非单一设计系统。

这不是“功能太多”本身造成的混乱，而是：

1. 配置、执行、结果、历史任务同时出现在同一个视觉层级。
2. 右侧 inspector 常驻，占据空间却重复显示低频信息。
3. 翻译和检测把所有高级选项平铺，用户无法判断当前处于哪一步。
4. 橙色、蓝色、红色同时承担选中、操作、错误和品牌语义。

建议后续正式迁移时只保留一套 token 和一套组件层；先迁移壳层、stepper、底部 RunBar、API 独立页，再逐步把现有业务逻辑接回去。
